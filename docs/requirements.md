# AgentSphere ESP32 功能需求草案

更新于 2026-11-19。本文供讨论，验证顺序、功能取舍和验收细节等候确认。

## 已确认的方向

- 本仓只负责 ESP32 设备端。对接的服务端是 AgentSphere，端与服务端通过设备协议协作。
- 首台聚焦微雪 ESP32-S3-Touch-AMOLED-1.75C。需求优先覆盖日常语音对话与小圆屏交互，为以后适配不同屏幕和外设留出板级边界。
- 「随时叫一声就能聊」是产品的主要用途。菜单可以承载新场景，儿童英语是第一个候选。
- 当前先定义功能。角色形象、名字和正式唤醒词暂缓决定。

## 固件基础

建议沿用微雪 1.75C 的 BSP 和 ESP-IDF 示例源码做板级适配。显示、触摸、收音和播报分别用相应示例确认，项目固件再实现 AgentSphere 的接入与语音交互。微雪提供的出厂 `.bin` 测试镜像用于验板和恢复出厂演示。后续技术选型核对复用组件的版本、许可和依赖，并验证显示、音频和唤醒能否在真机同时工作。

## 建议的验证顺序

| 阶段 | 体验目标 | 真机通过标准 |
| --- | --- | --- |
| A · 真机联调 | 设备联网，圆屏显示短期配对码，用户在 AgentSphere Web 认领，触屏录音并收到语音回答 | 从未绑定状态完成首次对话，重启和短时断网后均可恢复。配网失败或配对码过期时有明确的重试入口。 |
| B · 日常试用 | 免手唤醒、自然追问、结束对话，圆屏同步反馈状态 | 设备联网且处于支持唤醒的待机状态时，叫一声就能接着说问题。能追问两轮并主动结束，沉默超时回到待机。触屏可开始录音，也能停止本轮播报。 |
| C · 英语试点 | 从菜单进入一个短英语场景，开口互动并可随时退出 | 选定年龄及英语水平后，观察孩子能否找到入口、在约定的成人提示次数内完成一局、听懂重试提示并自行退出。是否随首版交付待定。 |

### 日常语音体验

- 主界面直接支持触屏说话。能区分待机、收音、等待回复、播报和离线。免手唤醒时，设备先给出视觉或短音反馈，再进入本轮收音。
- 建议待机时在端侧检测唤醒，设备进入明确的收音状态后才发送本轮音频。支持取消当前录音、等待或播报，并让用户明确知道这一轮已结束。
- 断网、服务超时或识别无结果时，给出可理解的提示并允许用户重试。断线恢复后继续原会话，重复提交不新开一轮。取消、过期或已退出场景的回复不应迟到播出。
- 在真实桌面距离、普通家庭背景声和亮屏／熄屏状态下，记录唤醒命中、误唤醒、唤醒反馈时间、问题首尾是否录全、说完到首句播报的等待时间。阈值等有真机数据后确认。

### 儿童英语候选玩法

建议先用一个口语情景验证，比如选冰淇淋口味。孩子说一个词就能继续，卡住可听示范或点选。日常聊天与陪练上下文分开，退出时结束本局，回到可用的主界面。

试点前确认成人如何配置孩子可用的场景、是否允许孩子免手进入通用聊天，以及录音、转写与练习记录是否保留、谁可查看。这些选择决定应用哪一套助手和工具权限。

## 端与服务端职责

| ESP32 | AgentSphere |
| --- | --- |
| 配网、屏幕与触摸、收音与播报、端侧唤醒、设备状态与菜单反馈 | 设备认领和授权、绑定默认助手、对话与会话、语音识别和合成服务、陪练内容和可用模式配置 |

按当前主仓状态，阶段 A 依赖 AgentSphere 尚待实现的 ESP32 Web 认领、设备鉴权与网关，以及语音识别、问答和合成回传的端到端接入。触屏收音与播报可以先单独验板。

配对码由设备向服务端申请，短期有效，只能认领一次。AgentSphere 确认设备归属，绑定认领账号选定的助手并预选默认助手，提供设备自己的凭据。验收覆盖过期码、两人同时认领同一码、已认领设备不能被另一个账号抢占、重启保留绑定、解绑后旧凭据失效。恢复出厂与再次认领规则待确认。

## 待讨论

1. 首个家用版本以日常对话为验收终点，还是同时交付一个儿童英语场景？若含英语，先确定儿童年龄、英语水平及能否独立使用通用对话。
2. 播报中是否支持语音打断，还是先用触屏停止？连续追问何时超时，是否支持显式开始新对话？熄屏和不同供电状态下如何待机？
3. 如何发起配网、换 Wi-Fi、解绑或恢复出厂？设备转让时如何重新认领？
4. 后续技术选型包括正式唤醒模型、语音服务、传输与音频格式。根据真机表现再定验收阈值。
